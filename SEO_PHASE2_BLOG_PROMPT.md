## 1. Post format (already used by the two posts)

`content/blog/<slug>.md`. The file name is the slug.

```
---
title: ...
description: ...
date: 2026-10-20
updated: 2026-11-02        (optional)
category: delivery         (one of: delivery, album-selection, guest-experience, studio-business, events, industry)
---
markdown body
```

- The body never contains an `# h1`; the title is the h1.
- A section headed exactly `## Frequently asked questions` contains `### question` headings, each followed by one or more answer paragraphs. These become FAQPage structured data. The section is still rendered on the page as normal.
- Category labels for display: delivery "Delivery", album-selection "Album selection", guest-experience "Guest experience", studio-business "Studio business", events "Events", industry "Industry".

## 2. Build step: `scripts/build-blog.mjs`

Cloudflare Workers cannot read `content/` at runtime, so posts are compiled into a TypeScript module at build time.

- Reads every `content/blog/*.md`, parses the frontmatter (simple `key: value` lines between the first two `---`; values are plain strings, trim them; no YAML library), and renders the body with `marked` (GFM on, so tables work).
- Post-process the HTML:
  - add `id` attributes to every `h2` and `h3` (slugified text) for anchor links;
  - wrap every `<table>` in `<div class="table-wrap">`;
  - external links (`http...` not on vyavasth.in) get `target="_blank" rel="noopener"`; internal links stay as they are.
- Extract FAQs: in the markdown, find `## Frequently asked questions`; each following `### ` heading is a question and the text until the next `###` or `##` or `---` line is the answer (strip markdown to plain text for the JSON-LD).
- Compute `readingMinutes = max(1, round(words / 200))`.
- **Validate and fail the build** (exit 1 with a clear message naming the file) when: a required field is missing; `date`/`updated` is not `YYYY-MM-DD`; the category is not in the list; two files share a slug; the slug is not `^[a-z0-9-]+$`; any title, description or body contains "—"; the body contains a line starting with `# `.
- Write `lib/blog/posts.generated.ts` exporting `BLOG_POSTS: BlogPost[]` sorted by date descending, with a header comment "Generated by scripts/build-blog.mjs. Do not edit." Commit-friendly output (stable order, pretty-printed). Do not gitignore it, so `tsc` and lint work without running the script.
- `package.json`: make `build` run the script first: `"build": "node scripts/build-blog.mjs && next build"`, and add `"blog": "node scripts/build-blog.mjs"`. Check `scripts/cf-deploy.sh` ends up calling `npm run build` (directly or through `opennextjs-cloudflare build`); if it calls `next build` directly, add the script call there too.

## 3. `lib/blog/index.ts` (pure, testable)

- `type BlogPost = { slug, title, description, date, updated?, category, html, faqs: {q,a}[], readingMinutes, headings: {id, text}[] }` (put the type here and import it in the generated file).
- `CATEGORY_LABELS` record.
- `todayInIndia(now = new Date()): string` → `YYYY-MM-DD` in `Asia/Kolkata` using `Intl.DateTimeFormat("en-CA", { timeZone: "Asia/Kolkata" })`.
- `isPublished(post, today)` → `post.date <= today`.
- `publishedPosts(today)` → published posts, newest first.
- `postBySlug(slug, today)` → the post only if published, else undefined.
- `relatedPosts(post, today, n = 3)` → published posts in the same category (excluding itself), newest first, topped up with other recent posts if fewer than `n`.
- `formatPostDate("2026-10-20")` → "20 Oct 2026".

## 4. Routes (all rendered at request time so future-dated posts appear on their date)

Every blog route and the sitemap must render per request, not at build time: use the documented way in this Next.js version (for example `export const dynamic = "force-dynamic"`). No `generateStaticParams` for posts, or future posts would be built in advance.

### `/blog` (`app/blog/page.tsx`)
- Metadata: title "Blog: wedding photo delivery and studio business guides | Vyavasth", description "Practical guides for Indian wedding and event photography studios: delivering photos, album selection, guest galleries, pricing and growing the studio.", canonical `/blog`.
- `LegalPageShell` title "Blog". Intro `<p>`: "Practical guides for wedding and event photography studios in India, from delivery and album selection to pricing and getting more bookings."
- List of `publishedPosts(todayInIndia())`: for each, a small muted line "{category label} · {date} · {n} min read", an h2 linking to `/blog/{slug}` with the title, and the description as `<p>`.
- JSON-LD: `Blog` with `@id: https://vyavasth.in/blog#blog`, `url`, `name: "Vyavasth Blog"`, `publisher: {"@id":"https://vyavasth.in/#organization"}`, and `blogPost` as a short array of `{ "@type":"BlogPosting", headline, url, datePublished }` for the listed posts. Plus `BreadcrumbList` Home > Blog.

### `/blog/[slug]` (`app/blog/[slug]/page.tsx`)
- `postBySlug(slug, todayInIndia())`; `notFound()` if undefined (this also hides future posts).
- `generateMetadata`: title `"{post.title} | Vyavasth"`, description, canonical `/blog/{slug}`, `openGraph` `type: "article"`, `publishedTime`, `modifiedTime`. Return `{}` metadata with `robots: { index: false }` when not found.
- Layout: use `LegalPageShell` with `title={post.title}` if its content column suits long reading; otherwise render `Nav` + a centred `max-w-[680px]` article + `Footer` exactly like LegalPageShell does. Under the title: muted line "By <a href="/about">Vyavasth Team</a> · {formatted date}{updated ? ` · Updated {formatted updated}` : ""} · {n} min read" and a category label.
- Body: `<div className={styles.prose} dangerouslySetInnerHTML={{ __html: post.html }} />`.
- After the body: a CTA block like the about page's ("Deliver your next wedding on Vyavasth." + WhatsApp button with `whatsappUrl("Hi, I read your blog post: " + post.title)` + link "See features" to `/features`), then h2 "More guides" with `relatedPosts` as links with their description.
- JSON-LD array: `BlogPosting` (`headline`, `description`, `datePublished`, `dateModified` (= updated or date), `author` and `publisher` both `{"@id":"https://vyavasth.in/#organization"}`, `mainEntityOfPage` = the URL, `image: "https://vyavasth.in/og-image.png"`, `inLanguage: "en-IN"`, `isPartOf: {"@id":"https://vyavasth.in/blog#blog"}`), `BreadcrumbList` Home > Blog > title, and `FAQPage` when `post.faqs.length > 0`.

### `app/blog/blog.module.css` (new CSS file allowed for this)
Readable long-form styles scoped under `.prose`: body text 17px/1.7 on phones and desktop, `h2` 24px with top margin 2.2em, `h3` 19px, paragraph spacing 1em, `ul/ol` with padding and list markers, `a` in `#C25A3A` underlined, `strong` 600, `table` full width 15px with cell padding and a thin bottom border per row (`rgba(26,18,8,0.08)`), `th` left-aligned bold, `.table-wrap { overflow-x: auto }` so the page never scrolls sideways on a 360px phone, `hr` as a thin rule with margin, inline `code` with a light background. Use the site's existing text colour variables if `globals.css` defines them (one grep for `--color` in `app/globals.css`), otherwise `#1A1208`.

### `/blog/rss.xml` (`app/blog/rss.xml/route.ts`)

## 7. Extra SEO details (do these too)

a) **Optional frontmatter fields** `seoTitle` and `updated`. The page `<title>` and `og:title` use `seoTitle` when present, else `title`. Append " | Vyavasth" only when the result stays at or under 65 characters; otherwise use the title alone. The visible h1 always uses `title`.

c) **Warnings, not failures** (print `WARN file: reason`, keep exit 0): effective title over 65 characters, description shorter than 110 or longer than 160 characters, fewer than 3 FAQs.
d) **"In this guide" table of contents:** when a post has 4 or more `h2` headings (not counting "Frequently asked questions"), render a short list of anchor links to them right after the meta line. Plain list, small text, no collapse.
e) **Visible breadcrumb** above the h1 on post pages: "Home / Blog / {category label}", with Home and Blog as links. Small muted text.
f) **BlogPosting extras:** `wordCount`, `articleSection` (category label).
g) **Caching:** in `next.config.ts` add `headers()` for `/blog`, `/blog/:path*` and `/sitemap.xml` setting `Cache-Control: public, max-age=0, s-maxage=3600, stale-while-revalidate=86400`, so pages rendered per request are still cached at the edge for an hour. Check the headers doc for this Next.js version first.
